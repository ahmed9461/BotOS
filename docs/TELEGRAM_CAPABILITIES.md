# قدرات Telegram في BotOS

آخر مراجعة: 2026-09-19. المرجع الفعلي للمحول هو مخططTDLib المثبت مع المكتبة، لا مجرد وجود اسم ميزة فيBot API. تجربة حساب المالك لا تنفذ نيابة عنه فيCI.

| القدرة | الحالة الحالية | حدود التحقق |
|---|---|---|
| شاشة الحساب والتفويض | موصولة بمحركTDLib وحالاته، مع موافقة واستعادة وخروج | حالات عرض مصطنعة ومحركJNI حقيقي؛ الدخول بحساب المالك ينتظر تجربته |
| البحث عن بوت | searchPublicChat ثمchatTypePrivate وuserTypeBot | لا اعتماد على لاحقة الاسم أو اسم التبويب |
| الرسائل النصية | تاريخ محدود، رسائل جديدة وتعديلات وحذف وحالات الإرسال | محول ومختزل ومنسق مختبرة ببيانات مصطنعة؛ ليست كل محتويات Telegram |
| Inline callback | بيانات أصلية وسياق ومراجعة ورسالة، ورد فعل من البروتوكول | لا استنتاج من نص الزر ولا إعادة فعل تلقائية بعد المهلة |
| Inline URL | تأكيد المستخدم ثم HTTP/HTTPS آمن | لاjavascript/file/intent أو فتح تلقائي |
| Reply keyboard | اللوحة النصية النشطة والأزرار النصية | طلب الهاتف والموقع والأنواع الخاصة غير منفذة؛ لا تُرسل دون موافقة |
| تغيير أزرار الرسالة | تعديلات في المكان نفسه ورفض أفعال قديمة | عزل الحساب والمحادثة وجيل العرض والمراجعة |
| Rich Messages | أمثلة محلية فقط في المعاينة | لا يدّعي أول إصدار ربط دعمRich الرسمي الكامل |
| الصور والصوت والفيديو والملفات | مؤجلة | تحتاج تنزيلًا وصلاحيات وحدودًا ومشغلات فعلية |
| Streaming drafts | مؤجل | فصل المؤقت عن النهائي وإيقاف وعزل وبروتوكول مثبت |
| Mini Apps وPayments وLogin URLs | مؤجلة | لا تنفيذ تخميني؛ معالجة مخصصة ومراجعة أمان |
| أنواع غير معروفة | بديل واضح أو فعل معطل | لا نجاح وهمي ولا تنفيذ غير موثوق |

## ثوابت

لا AI يتخمنcallback. ترتيب الأفعال وبياناتها منTelegram نفسه. لا/start عند كل تبديل تبويب؛ البدء زر صريح. رجوع النظام مستقل عن زر رجوع البوت. لا نقل موقع أو رقم هاتف دون إذن. جلسة المستخدم ليست محدودة الصلاحيات بالبروتوكول لمجرد أن الواجهة تعرض بوتات؛ الوصول مقيد عمليًا بحاجات المنتج، دون مزامنة جهات اتصال أو جلب محادثات أخرى بلا حاجة.
