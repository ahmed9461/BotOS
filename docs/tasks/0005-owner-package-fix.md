# 0005 — تصحيح قارئ دليل حزمة المالك

2026-09-19. خطة قبل تعديل المصدر، فوق acad9a14. لا تعديل للتطبيق أو الاختبارات الوظيفية أو الأيقونة. طلب المالك المتابعة داخل الجلسة دون انتظار الجدولة.

## الدليل والتشخيص

نجح بناء ownerPreview المهيأ وlint واختبار البدء الحقيقي 1/1 في التشغيل35398234294، job105771926264. ظهر بعدها خطأ التحقق من حزمة التسليم في owner_delivery.py قبل خطوة التشفير. لا artifact مهيأ نُشر، والتنظيف نجح. لا يُسجل التشغيل كله ناجحًا ولا تُخفى خطوة فاشلة.

بفحص XML الفعلي من CI32 ظهر أن الجذر testsuites، وتوجد testcase داخل testsuite، بينما package_owner يستعمل report.findall('testcase') الذي يعيد صفرًا لهذا التقرير. أُعيد إنتاج الاختلاف محليًا على التقرير الأصلي:14 حالة عبر .//testcase وصفر عبر المسار المباشر، ومنها OwnerBuildSmokeTest بالاسم المتوقع. هذه علة مؤكدة في القارئ؛ لا نفترض عدم وجود مانع تالٍ قبل إعادة التحقق. تقرير التشغيل المهيأ حُذف بعد الفشل، لذلك لا ندعي قراءة ملفه المحلي.

## خطة التصحيح

1. استخراج تحقق XML يدعم testsuite أو testsuites المتداخلين، مع اشتراط الحالة المطلوبة بالاسم، وعدد1، وصفر فشل/خطأ/تخطي في الجذر والأبناء؛ رفض التقارير المتعارضة أو الناقصة. لا إزالة لبوابة اختبار البدء.
2. أخذ اسم APK من output-metadata.json بدل افتراض اسم الملف، والتحقق من variant/applicationId ونوع APK وعدم خروج المسار عن مجلده، ومن وجود ملف واحد فقط. لا اعتبار بيانات المصدر المولدة آمنة للنشر.
3. إضافة مراحل تشخيص ذات أسماء ثابتة غير حساسة لتمييز فشل التقرير من البصمة أو التوقيع أو المحاذاة؛ لا طباعة استثناءات أو بيئة أو محتوى أسرار.
4. اختبارات قارئ التقرير والشكل المتداخل الموافق للدليل الفعلي، ورفض الفشل المتداخل والاختبار الخاطئ والعدد المتعارض، ومسار APK الخبيث، واختبار تركيب الحزمة بملفات مصطنعة. لا تستبدل اختبارات Python فحص apksigner/zipalign الحقيقي في التسليم.
5. تعطيل طلب التسليم القديم أثناء التصحيح؛ إعادة CI الكامل55JVM و8native و14app مع الاختبارات الجديدة، ثم تثبيت طلب التسليم على المصدر الناجح وإعادة البناء المهيأ مباشرة، دون انتظار ساعة أو إعادة عمياء للفشل.
6. فحص الغلاف والبصمة والتوقيع الخاص ومحتوىAPK، وتحديث الأدلة والذاكرة والسجل وPR ثم التسليم. حدود تسجيل الحساب وRich/الوسائط والتصميم كما هي.

## القبول والتراجع

نجاح نفس اختبارات التطبيق ثم بوابة البدء المهيأ والتغليف والتشفير دون تسريب. لا تغيير لشروط الموافقة أو لمسافات الكيبورد أو حذف اختبار، ولا رفع plaintext عند الفشل. التراجع عن تصحيح أدوات التسليم وحده، دون تغيير واجهة أو بيانات المستخدم أو force-push. عدم نجاح خطوة لاحقة يسجل برمزها الثابت ويعالج من دليلها.
