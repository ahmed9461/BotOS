## التنفيذ المرتب

1. إغلاق نتيجة native الحالية وقراءة تقاريرها؛ أي فشل جديد يُشخّص قبل تسليم أو تجاوز بوابة التحقق. لا إعادة اختبار عشوائية أو تغيير حدود focus/IME/gap.
2. إضافة مصدر ConnectionPreferences فعلي في ملف DataStore مستقل داخل noBackupFilesDir، ومنسق واحد بعمر Application وفتح JNI خارج main thread. لا اتصال في تثبيت جديد قبل الموافقة.
3. وصل app بوحدة core:tdlib مع تهيئة المصدر الأصلي قبل البناء. أضف وجهة الحساب بنفس نظام التصميم، من رابط بسيط في المظهر؛ احتفظ بالتبويبات الحالية. حالة غير مهيأة لا تحتوي نموذج هاتف أو رمز.
4. عرض حالات PHONE/CODE/PASSWORD/EMAIL/EMAIL_CODE من AccountCoordinator فقط، وحالات إضافية صريحة دون ادعاء دعمها. المدخلات transient وليست rememberSaveable أو SavedState؛ FLAG_SECURE أثناء المدخلات، وإزالة المدخلات عند تبدل المرحلة أو إرسالها. تمييز نجاح التهيئة من نجاح الهوية.
5. ربط إذن الاستعادة والخروج المؤكد بالمنسق، وعدم مسح أسماء البوتات أو تفضيلات الشكل. استبعاد البيانات من backup/device transfer ومراجعة Manifest. لا تغيير حساب أو دخول عبر CI.
6. اختبارات واجهة بإشارات مصطنعة للتهيئة والموافقة والتبدل والرموز/السرية؛ واختبارات مخزن الإذن الفعلي. تبقى36JVM و8JNI/Keystore و3UI السابقة مطلوبة. إعادة قراءة XML والصور بدل الاكتفاء بلون نجاح workflow.
7. وثّق النتائج والحدود ونقطة الاستئناف في الذاكرة والسجل وTESTING والخطة وPR. لا تسلّم معاينة قديمة على أنها ربط بوتات مكتمل. شريحة البوتات ذات المخطط الحقيقي تأتي بعد نجاح الحساب، وفق الخطوة5 في الخطة الأصلية.

## البناء والسرية

تجميع التطبيق مع JNI يتطلب مخرجات المصدر المثبت لا مكتبة مجهولة. وحّد مسار CI عند الحاجة بحيث يختبر المحرك والتطبيق معًا دون تكرار المحاكيات لنفس المصدر؛ لا حذف لحالة اختبار. الاختبارات العامة بلا أسرار. يُستخدم زوج GitHub Secrets فقط في مسار دفع موثوق محدد، بلا cache أو build scan أو مصادر مولدة في artifacts. لا APK مهيأ قبل اكتمال الوظائف والاختبارات؛ بيانات العميل داخله ليست سرًا غير قابل للاستخراج. التوقيع الدائم ليس متوفرًا؛ لا تعالج اختلاف الشهادة بحذف بيانات المالك.

## القبول والتراجع

منسق واحد، وموافقة فعلية، ونصوص عربية/إنجليزية بسيطة، ولا إعادة تهيئة في كل تبويب. المدخلات لا تعود بعد recreation، وFLAG_SECURE يضبط للمدخلات ويرفع عند مغادرتها. الإذن يستعاد محليًا ولا ينتقل في backup. التصميم والأيقونة وملكية IME ثابتة. التراجع عبرrevert لشريحة الحساب وحدها، دون force-push أو دمج أو إخفاء فشل.
