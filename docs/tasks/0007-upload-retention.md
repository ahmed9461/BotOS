# 0007-D — سياسة ملفات الإرسال قبل ربط الواجهة

22 سبتمبر 2026. تفصيل مكمل لخطة0007، مكتوب قبل تنفيذ مخزن ملفات الرفع.

## المشكلة التي نمنعها

استجابة sendMessage قد تعني رسالة قيد الرفع لا وصولًا نهائيًا. حذف inputFileLocal عند إغلاق المنتقي أو تغيير البوت يمكن أن يقطع الرفع. إعادة الطلب بعد مهلة قد تكرر الإرسال. يجب إبقاء ملف الإدخال، وربطه بهدف الإرسال لحظة اختيار المرفق، وعدم استخدام حالة المحادثة الجديدة بعد رجوع المنتقي.

## القرار

- نسخة محلية متدفقة من URI اختاره المستخدم، تحت `noBackupFilesDir/telegram/main/files/botos_outgoing`. لا صلاحية قراءة كل التخزين، ولا Base64 أو تحميل الملف كاملًا إلى الذاكرة.
- حد أولي للملف50MiB، وإجمالي الملفات المحلية200MiB وعدد32. الصورة تعاد كتابتها JPEG بأبعاد مدروسة وإزالة البيانات الوصفية، مع الالتزام بقيود inputPhoto؛ الفيديو غير القابل للإرسال كفيديو يعرض خيار ملف بدل نجاح وهمي.
- المنتقي لا يرسل شيئًا. تعرض معاينة مع اسم الهدف والوصف وأزرار إرسال وإلغاء. أي تبديل حساب/محادثة قبل التأكيد يلغي المعاينة ويمنع الإرسال إلى هدف آخر.
- يُكتب سجل محلي صغير قبل إرسال الطلب، بمعرف عشوائي وsending_id الموثق في messageSendOptions، ثم يرتبط بمعرف الرسالة من الاستجابة أو updateNewMessage. السجل خارج Git والنسخ الاحتياطي.
- مراقب رفع مستقل عن الشاشة يتابع updateMessageSendSucceeded/Failed. لا يُلغى الرفع بسبب التبديل بين البوتات. يحتفظ بالملفات غير المؤكدة ولا يعيد إرسالها تلقائيًا. عند عودة العملية، يسأل getMessage للمعرفات المعروفة فقط؛ المجهولة تبقى غير مؤكدة، لا تحذف تخمينًا.
- الملفات المكتملة يمكن إخلاؤها عند بلوغ الحصة، بعد تأكيد النجاح؛ الملفات قيد الإرسال أو غير المؤكدة لا تُمحى بالوقت وحده. ملفات المعاينة التي لم تدخل سجل إرسال تزال عند الإلغاء. الخروج المؤكد يمحو مجلد الجلسة بما فيه هذه الملفات.
- الشاشات لا تعتبر نجاح حفظ الملف أو قبول TDLib للطلب رسالة وصلت. تبقى حالة pending/failed من Telegram مصدر العرض. الميكروفون يعمل بإذن صريح، مع إيقاف وتأكيد قبل الإرسال، ويتوقف عند مغادرة التطبيق.

## اختبارات القبول

فقد نتيجة الطلب، update نهائي يسبق الاستجابة، تبديل البوت أثناء المنتقي/الاستيراد، فشل الإذن، حد الحجم والمساحة، إلغاء قبل الإرسال، بقاء الملفات عبر إعادة إنشاء الشاشة، إعادة فتح السجل بعد العملية، ورفض إرسال ملف خارج الجذر الخاص. اختبار الإدخال الحالي بالـsending_id لا يعطل حقول الرسائل النصية السابقة.

هذه خطة وليست إعلان تنفيذ أو نجاح. يجب تسجيل أي فرق فعلي أو قدرة مؤجلة في0007-progress قبل تسليم APK.
