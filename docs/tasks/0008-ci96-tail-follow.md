## التشخيص والتنفيذ المرتب

1. شرط المتابعة الحالي يقرأ `canScrollForward` بعد إعادة قياس القائمة بوصول الرسالة؛ بهذا قد يفقد كون القارئ كان عند النهاية قبل الإضافة. حالات حفظ موضع التاريخ والقفز الصريح والإرسال في الاختبار نفسه نجحت، لكن متابعة الوارد بعد الإرسال فشلت.
2. استخدم نية متابعة ثابتة للمحادثة تشترك فيها الرسائل النهائية والبث المؤقت؛ تغيّرها حركة القارئ أو القفز/الإرسال، لا مجرد ازدياد ارتفاع المحتوى. احمِ التمرير البرمجي من تفسيره كابتعاد يدوي. لا مهلات عشوائية أو تعطيل الاختبار.
3. قوِّ اختبار القفز الحالي بإضافات واردة متتابعة عند النهاية، ثم ابتعاد آخر عن النهاية ووصول وارد يحفظ موضع القراءة. تبقى جميع الشروط السابقة والعدد85؛ لا حذف لحالات الخط الكبير أو الصور أو IME أو الأمان.
4. حدّث الذاكرة والسجل، شغّل فحوص المصدر المتاحة ثم CI مطابق، وافتح تقارير XML والصور27 والـIME. أصلح أي فشل قبل طلب نسخة المالك.
5. بعد نجاح المصدر: مسار0.6 والتوقيع الدائم وطلبCMS والترقية0.5→0.6 كما في خطة التسليم. request يبقىdisabled حتى تحقق المصدر.
