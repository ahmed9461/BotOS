# سجل القرارات

## ADR-001 — عميل مستخدم لا Bot API

2026-09-18، معتمد. BotOS يتفاعل باسم حساب المستخدم عبر TDLib عند تنفيذ النقل. لا يحتاج توكنات البوتات أو تغيير webhooks الخاصة بها. المحتوى والأفعال تأتي من البروتوكول دون تكامل منفصل لكل بوت.
المصدر: https://core.telegram.org/tdlib

## ADR-002 — شرائح متكاملة وتوثيق قبل التنفيذ

معتمد. تبدأ الشريحة بمعاينة محلية صريحة لاختبار الواجهات ومحرك الرسائل، ثم يضاف الاتصال الحقيقي مع حماية الجلسة. لا شاشة تحقق وهمية أو نجاح مزيف. المتطلبات والخطة والكود والاختبارات والذاكرة حزمة واحدة.

## ADR-003 — وحدات قليلة ذات مسؤوليات واضحة

معتمد. app ووحدات model وtelegram وdata وdesignsystem. تستخرج وحدات الميزات عند الحاجة، ولا تنشأ عشرات المجلدات الفارغة. لا Room يكرر قاعدة TDLib، ولا WorkManager لاتصال فوري، ولا Hilt دون حاجة فعلية.
المصدر: https://developer.android.com/topic/architecture

## ADR-004 — Navigation 3

معتمد بعد مراجعة 2026-09-18. اختيار الإصدار المستقر 1.1.7 المبني لـCompose، لا الإصدار المرشح الظاهر في بعض أمثلة الوثائق. المقترح السابق Navigation 2.10.1 لا يطبق تلقائيًا لمجرد ذكره في المحادثة.
المصدر: https://developer.android.com/jetpack/androidx/releases/navigation3

## ADR-005 — الهوية الأولى والحركة

كان الاتجاه الأول Pearl / Graphite / Mauve، مع رموز أصلية وثيمات النظام والفاتح والداكن واتجاه العربية وتقليل الحركة. **حدّث ADR-006 ألوان الواجهة وترتيبها بعد تجربة المالك.** تبقى أيقونة launcher الأصلية دون تغيير. لا تضحية باستجابة الضغط لأجل حركة طويلة، ولا مصطلحات هندسية للمستخدم.

## ADR-006 — مراجعة الواجهة بعد اختبار المالك

معتمد للتنفيذ. انظر [القرار المفصل](decisions/0006-ui-refinement.md) و[خطة 0003](tasks/0003-ui-refinement.md). مالك واحد لمساحات النظام والكيبورد، وقراءة الحالة داخل كل وجهة، وهوية داخلية Porcelain / Graphite / Iris مع إبقاء الأيقونة والتخزين. اختبار تشغيل للمفتاح والثيم والكيبورد والحفظ ولقطات فعلية قبل إعلان النجاح.

## ADR-007 — اعتماد المالك للتصميم وتثبيت مرجعه

2026-09-18، معتمد من المالك بعد الجولة الثانية. المصدر: رسالته الصريحة «الان تصميم التطبيق ابدااااع جميل جدااااا يعتمد تماما». مرجع المصدر في المستودع وقت التوثيق هو `158c5258da82e0146d1f632446e65653e46e3649`، الجولة 0.2، وليس إثباتًا لبصمة ملف مثبت على جهازه.

القرار: تثبيت نظام Porcelain / Graphite / Iris والواجهات والتبويبات والأيقونة الأصلية كأساس للميزات التالية. تستخدم الشاشات الجديدة المكونات والألوان القائمة. لا تبديل للهوية أو الألوان الأساسية أو الأيقونة أو إعادة ترتيب جوهرية دون موافقة جديدة. تستمر إصلاحات العيوب وإمكانية الوصول والأداء مع الحفاظ على الشكل؛ الآثار البصرية الجوهرية تحتاج مراجعة مسبقة.

السبب: تحقق رضا المالك عن الاتجاه الجديد؛ إعادة تصميمه دون طلب تهدر ما تم اعتماده وتفصل الميزات اللاحقة عن الهوية. النتيجة: توجّه المرحلة التالية لإغلاق التحقق الفني ثم وظائف Telegram، لا لإعادة فتح اختيار الألوان.

الحدود: قبول بصري لا يعني اكتمال اختبارات أو إذن دمج أو اتصال حي. لا تغيير لملفات التطبيق أو الأيقونة ضمن هذا القرار. التنفيذ التوثيقي في [ملحق الاعتماد](tasks/0003-design-approval.md)، والمرجع البصري في [UI_GUIDELINES](UI_GUIDELINES.md).
