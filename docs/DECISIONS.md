# سجل القرارات

## ADR-001 — عميل مستخدم لا Bot API

2026-09-18، معتمد. BotOS يعرض ويتفاعل باسم حساب المستخدم عبر TDLib عند تنفيذ النقل. لا يحتاج توكنات البوتات، ولا يغير webhooks الخاصة بها. السبب: البروتوكول يحدد المحتوى والأفعال دون تكامل منفصل لكل بوت. المصدر: https://core.telegram.org/tdlib

## ADR-002 — شرائح متكاملة وتوثيق قبل التنفيذ

معتمد. أول شريحة محلية واضحة تختبر تصميم التبويبات ومحرك الرسائل، ثم اتصال حقيقي مع حماية الجلسة. لا شاشة تحقق وهمية ولا نجاح مزيف. الخطة/الكود/الاختبار/الذاكرة حزمة واحدة.

## ADR-003 — وحدات قليلة ذات مسؤوليات واضحة

معتمد. app + core model/telegram/data/designsystem الآن. اقتراح عشرات الوحدات وExplore سابقًا ليس التزامًا ببنائها فارغة. Room وWorkManager وHilt تُضاف بقرار مدعوم عند الحاجة، ولا تكرر قاعدة بيانات TDLib. المصدر المعماري: https://developer.android.com/topic/architecture

## ADR-004 — Navigation 3 لا تثبيت Navigation 2 تلقائيًا

معتمد بعد مراجعة 2026-09-18. Navigation 3 لديها stable 1.1.7، وهي مبنية لـCompose. أمثلة صفحة الإصدار تستخدم RC؛ نختار stable صراحة. المقترح السابق Navigation 2.10.1 لا يُطبق آليًا لمجرد أنه ذُكر في المحادثة. المصدر: https://developer.android.com/jetpack/androidx/releases/navigation3

## ADR-005 — الهوية والحركة

معتمد. Pearl/Graphite/Mauve، أصول vector أصلية، عربي RTL، ثيم System/Light/Dark، تقليل الحركة. لا تضحّي باستجابة اللمس لأجل انتقال طويل، ولا تخلط المصطلحات الهندسية بنصوص المنتج.
