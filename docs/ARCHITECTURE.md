# بنية BotOS

آخر مراجعة: 2026-09-19. ست وحدات فعلية. التطبيق موصول الآن بمحرك الحساب ومحادثات البوتات، مع بقاء معاينة محلية مستقلة. مصدر الحساب والمحادثات اجتاز التشغيل35395498382؛ اعتماد نسخة تسليم معينة يتطلب أيضًا دليل البناء المهيأ والتوقيع في OWNER_DELIVERY وTESTING.

## الوحدات ومصادر الحقيقة

- `core:model`: نماذج مستقلة عن Android وتطبيع أسماء البوتات وعرض الرسائل والأفعال.
- `core:telegram`: معاينة مستقلة؛ وعقود TdRpc/TdTransport والتفويض وAccountCoordinator وBotConversations ومحول الرسائل ومختزلها. بيانات البروتوكول لا تمر إلى Composables.
- `core:tdlib`: JSONJava الرسمي وAndroidTelegramSession وSessionVault. مصدر المكتبة ثابت ومتطابق مع Java وschema؛ استقبال واحد لكل عملية، ومفتاح قاعدة البيانات محمي عبرKeystore.
- `core:data`: WorkspaceStore للأسماء والترتيب والثيمات، وAccountRestoreStore المنفصل لإذن استعادة الحساب. لا نسخ مكرر لقاعدة TDLib، ولا تغيير لمفاتيح المكتبة القديمة.
- `core:designsystem`: الألوان والأشكال والحركة والرموز المعتمدة. أيقونة launcher الأصلية لم تتغير.
- `app`: BotOsApplication يملك منسق حساب واحدًا، وViewModels والتنقل والشاشات ومحرك العرض. يعتمد فعليًا علىcore:tdlib؛ شاشة غير مهيأة لا تجمع بيانات دخول.

## الحساب والجلسة

`UI intent → AccountCoordinator → AccountSession/TdRpc → TDLib updates → immutable state → AccountRoute`

تسبق الموافقة أول فتح للجلسة. لا يدل ردOk على نجاح المصادقة؛ تنتقل الشاشة حسب التحديثات، ويحددgetMe الحساب بعدREADY. تستخدم الاستعادة إذنًا محفوظًا منفصلًا، وتمنع الأجيال والمزامنة تأثير رد متأخر بعد الخروج. ينفذ التخزين وفتحJNI خارج مسار الرسم. المدخلات الحساسة مؤقتة ولا تدخلSavedState أوlogs أوbackup، والنافذة محمية أثناء إدخالها. close ليسlogOut؛ محو بيانات الجلسة يتبع الإقرار والإغلاق، وفقد المفتاح يفشل بوضوح دون محو ضمني. التفاصيل فيACCOUNT_INTEGRATION وTELEGRAM_RUNTIME وSECURITY.

## محادثات البوتات

`ReadyAccount → BotConversations → searchPublicChat/getUser → verified bot → history/updates → reducer → LiveBotPanel`

لا يكفي اسم ينتهي بـbot؛ يجبchatTypePrivate وuserTypeBot. التاريخ محدود، والنصوص والتعديلات والحذف ولوحاتReply وأفعالInline تعالج من المخطط المثبت. عزل الحساب والمحادثة وجيل العرض ومراجعة الرسالة يمنع أزرارًا قديمة أو نتائج طلب متأخر. لا يعيد timeout إرسال الفعل تلقائيًا. يعالج المختزل سباق معرف إرسال مؤقت ومعرف نهائي، ولا يطغى تاريخ قديم على تحديث أحدث. بدء البوت صريح وليس عند كل تبويب. التفاصيل فيLIVE_BOTS.

## التنقل والواجهة

Navigation3 يحتفظ بسجل الشاشات. الوجهات الجذرية: المساحة والمكتبة والمظهر؛ ثم المحرر والحساب. تجمع كل وجهة حالتها داخلNavEntry، ولا تعتمد لقطة تفضيلات قديمة أو تغيير مفتاح الشاشة لإصلاحها. رجوع النظام لا يضغط زر رجوع البوت. المسودات الحية مؤقتة ومعزولة، والمدخلات الحساسة ليست محفوظة كحالة شاشة.

BotOsApp وحده يطبق اتحادsystemBars/displayCutout/IME ويستهلكه؛ لاimePadding إضافي داخلcomposer أو المحرر. يختفي التنقل وتصغر المقدمة أثناء الكتابة. الهوية Porcelain/Graphite/Iris والثيمات وRTL والأيقونة معتمدة، ولا يغيرها البناء التجريبي.

## البناء والتسليم

CI العادي بلا أسرار ويختبر المحرك والجهاز والواجهة في مسار واحد. ownerPreview بمعرف مستقل يثبت بجانب المعاينات السابقة ولا يمسح بياناتها. التسليم الخاص من مصدر اختبر كاملًا، ويحقن إعدادات Telegram في مسار موثوق دونcache أو مصدر مولد مكشوف. APK المهيأ لا ينشر مكشوفًا في المستودع العام، والتوقيع الخاص النهائي خارجGit. راجعOWNER_DELIVERY للحالة الفعلية لا مجرد وجودworkflow.

## حدود الأداء والقدرات

قوائم كسولة ومفاتيح مستقرة وحدود حجم وسعة وعمق، ولا تحميل وسائط كبيرة تلقائيًا. الأفعال غير المدعومة لا تنفذ بالتخمين. Rich/الوسائط/streaming/MiniApps والمدفوعات ليست جزءًا من أول نسخة الربط النصي. الاختبارات المصطنعة للمحادثات لا تعني تجربة حساب المستخدم. نجاح JNI ومحاذاة ELF لا يثبتruntime16KB أوFPS/TalkBack أو كل الأجهزة.
