# البنية المعمارية

الحالة: تصميم معتمد للشريحة الأولى، وليس ادعاء بوجود الوحدات قبل بنائها.

## التدفق

`UI intent → ViewModel → Repository/Gateway → immutable state → Compose`.

عند ربط Telegram: `TDLib update → adapter → normalized message/action → per-chat state → renderer`. الواجهة لا تستقبل JSON خامًا أو TdApi objects؛ جميع استدعاءات الشبكة والتخزين خارج thread الواجهة.

## الوحدات المستهدفة الآن

- `:core:model`: Kotlin/JVM خالص؛ نماذج البوت/الرسالة/الكتل/الأزرار، تطبيع المدخلات، قواعد الهوية وعزل الحالة وحماية الأفعال القديمة. بلا Android وبدون اعتماد على UI.
- `:core:telegram`: عقد Gateway وحدود adapter وسياسة القدرات. التنفيذ المحلي للمعاينة لا يتنكر كاتصال حقيقي. JNI والجلسة في المرحلة التالية.
- `:core:data`: DataStore للإعدادات وقائمة البوتات المحلية؛ نسخة واحدة من store لكل ملف. لا سجل رسائل دائم هنا.
- `:core:designsystem`: الألوان والأشكال والأيقونات والحركة المشتركة.
- `:app`: نقطة التجميع وViewModels والتنقل وواجهات features والـrenderer.

تستخرج feature modules لاحقًا عندما تنمو المسؤوليات، بدل إنشاء عشرات وحدات فارغة. Domain/use cases عند وجود إعادة استخدام أو تعقيد حقيقي. حقن الاعتمادات يدوي وصريح في نقطة التجميع أولًا، لا service locator مخفي.

## مصادر الحقيقة

DataStore: الاسم المحلي والترتيب والتفضيلات. TDLib عند ربطه: الحالة والمحادثات والرسائل والملفات. ViewModel: حالة العرض المؤقتة، والانتظار ونتائج الأفعال. كل محادثة مفتاحها account/chat؛ لا استخدام أسماء التبويبات كمعرفات أو خلط callbacks بين البوتات.

## التنقل

Navigation 3 للشاشات، مع حالة محفوظة للتبويب والتمرير ومسودة الكتابة لكل بوت. الرجوع من شاشة إعدادات يرجع للمكان الذي فُتحت منه. Back الخاص بالنظام لا يضغط زر «رجوع» داخل البوت ولا يخمن بياناته. فتح تبويب لا يرسل `/start` تلقائيًا كل مرة. بدء محادثة فعل واعٍ مرة مطلوبة.

## المحتوى الديناميكي

نماذج مستقلة لرسائل النص والكتل والأفعال، مع IDs مستقرة للمحادثة والرسالة ومراجعتها. تعديل الرسالة يستبدل محتواها وأزرارها في المكان نفسه. الردود القديمة والطلبات المتأخرة لا تنفذ فعلًا على رسالة أحدث. ترتيب الصفوف والبيانات الأصلية محفوظان؛ RTL يغير العرض لا معنى callback.

لا تحوّل Markdown عاديًا إلى Telegram Rich Message مزعومة؛ لكل منهما تمثيل ومصدر وقدرات منفصلة. نوع غير معروف يعرض تنبيهًا مفهومًا وخيار فتح في Telegram عند توفر رابط آمن بدل crash أو زر مزيف.

## التوسع والأداء

قوائم كسولة ومفاتيح مستقرة، حد للمحتوى المحمل والعمق، جمع lifecycle-aware، تجميع تحديثات العرض فقط دون إسقاط الأحداث الوظيفية، وإلغاء أعمال الصفحات المغادرة. لا تحميل فيديوهات أو أرشيفات كاملة تلقائيًا. قياس الأداء على release لاحقًا شرط قبل ادعاء 60/120fps.
