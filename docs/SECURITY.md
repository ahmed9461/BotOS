# الأمان والخصوصية

## ممنوع في Git أو تقارير الاختبار

api_hash حقيقي، توكنات، أكواد الدخول و2FA، قواعد جلسة TDLib، محتوى رسائل مستخدمين، ملفاتهم أو بياناتهم الشخصية. Fixtures مصطنعة فقط. التشخيص بلا محتوى رسائل أو callback payloads، ولا analytics افتراضية.

## عند تفعيل Telegram

api_id/api_hash يخصان التطبيق ويحفظان في local.properties أو أسرار بناء مخصصة، وليس شاشات عامة للمستخدم. لا تدّع أن أسرار العميل المضمنة في APK غير قابلة للاستخراج. مفاتيح الجلسة وقاعدة TDLib محليًا فقط؛ حماية مفتاح قاعدة البيانات بواسطة Android Keystore، استبعاد قواعد الجلسة من backup، وعدم حفظ كود الدخول أو كلمة المرور. تسجيل الخروج يجب أن ينهي الجلسة ويمحو الملفات المعنية، واختبار ذلك قبل التسليم.

عرض البوتات فقط لا يجعل جلسة Telegram محدودة الصلاحيات بالبروتوكول؛ يجب توضيح طبيعة الحساب، تقليل الوصول، وعدم جلب محادثات أخرى دون حاجة. لا خادم مركزي لجلسات المستخدم.

## الأفعال والوسائط

موافقة صريحة للموقع/رقم الهاتف/الملف/الدفع وفتح الروابط الخارجية. منع file/javascript/intent غير الموثوق. لا تنفيذ HTML أو scripts مرسلة في رسائل البوت. limits للعمق والحجم وعدد الملفات. لا تعيد ضغطات callback المالية تلقائيًا عند مهلة أو انقطاع؛ الحالة غير المؤكدة تستدعي تحديثًا/تأكيدًا لا تكرارًا أعمى.

## قبل النشر

مراجعة شروط Telegram ومنها الخصوصية والشفافية وسلوك الوظائف الأساسية، ولا افتراض أن التركيز على البوتات يعطي إعفاءً. لا شعار Telegram أو أصول Apple. لا منع انقضاء الرسائل أو تحريف read/typing. صلاحيات وتوقيع واختبارات native 16KB pages ومراجعة الاعتمادات قبل live.
