# ذاكرة BotOS — نقطة الاستئناف

آخر تحديث: 2026-09-18. المهمة النشطة: [0005 — ربط الحساب والبوتات](tasks/0005-account-connection.md). **الخطوة الأولى مكتوبة وقيد التحقق، وبقية P2b لم تُنفذ بعد.** ملحقها [0005-account-coordinator](tasks/0005-account-coordinator.md). فرع العمل `feat/telegram-connection` فوق `191c0466`؛ خطة `c67f38de` سبقت الكود.

## اقرأ قبل التنفيذ

AGENTS ثم الذاكرة والبنية والخارطة والقرارات والأمان والقدرات والخطة والكود والاختبارات. افحص الفرع وآخر التغييرات. خطط ثم نفذ حسب الترتيب ثم اختبر ووثق؛ لا تتجاوز فشلًا، ولا تعتمد على المحادثة أو وجود ملف اختبار بدل الدليل.

## المنتج والهوية الثابتة

Android يجمع بوتات يختارها المستخدم في تبويبات يسميها ويرتبها، ويعرض محتواها وأفعالها دون تكامل منفصل لكل بوت أو AI يتخمن الأزرار. تصميم Porcelain / Graphite / Iris والأيقونة الأصلية معتمدان في ADR-007 عند158c5258. لا تغيير جوهري للألوان أو ترتيب الواجهات أو الأيقونة دون موافقة. الشاشات الجديدة تستخدم نفس المكونات. العربية RTL والثيمات وتقليل الحركة وأسماء البوتات وترتيبها ومفاتيح DataStore محفوظة.

BotOsApp وحده يملك اتحاد مساحات النظام والكيبورد؛ لا imePadding في composer. كل Route يجمع حالته داخل NavEntry، ولا تعاد الشاشة قسرًا لتحديث toggle.

## ما يعمل فعلًا

P2a مكتملة كمحرك مستقل: TDLib/JSONJava مثبت، TdRpc/TdTransport، Authorization، وAndroidTelegramSession بملكية استقبال حصرية، وSessionVault يحمي مفتاح قاعدة الجلسة عبر Keystore/AES-GCM. close يحفظ البيانات، وlogOut ينتظر الإقرار والإغلاق ثم يمحو ملفات الجلسة فقط. فقد المفتاح أو تلفه لا يمحو البيانات ضمنيًا.

app ما زال معاينة0.2 محلية؛ لا ربط بالمحرك أو شاشة دخول أو إرسال إلى بوت حي. حفظ اسم بوت لا يثبت هويته، وفتح Telegram الخارجي ليس تكاملًا داخليًا. لا تُرسل معاينة0.2 بوصفها النسخة المتصلة التي ينتظرها المالك.

## المنفذ الآن في الخطوة الأولى من P2b

أضيف AccountSession وAccountSessionFactory وConnectionPreferences وAccountCoordinator داخل core:telegram، ونُفذت الواجهة في AndroidTelegramSession دون تغيير الحماية. لا عميل جديد لكل شاشة. التهيئة والموافقة قبل الفتح، AuthStep الحقيقي قبل التقدم، وgetMe بعدREADY فقط لتحديد هوية الحساب. المدخلات الحساسة لا تدخل AccountState أو التشخيص. جيل الجلسة يمنع الكائن القديم من تغيير الحساب الجديد.

الاستعادة لا تعمل في تثبيت جديد، وإذنها لا يُحفظ إلا بعد READY وهوية سليمة. طلب الخروج يوقف الاستعادة قبل محاولة إلغاء الجلسة؛ mutex منفصل يسلسل كتابة الإذن حتى لا يعيد جواب هوية متأخر تفعيله. الإلغاء لا يُعد خروجًا مؤكدًا أو إذن محو. فشل الخروج والتنظيف حالتان واضحتان.

كتبت **15 حالة JVM جديدة** ببدائل مصطنعة لا تتصل بالشبكة. يجب تشغيلها مع21حالة السابقة ثم8native و3UI وlint/build؛ لا نجاح مفترض حتى قراءةCI. لم يُربط المنسق بـapp أو DataStore حقيقي أو بيانات تطبيق بعد.
