# ذاكرة BotOS — نقطة الاستئناف

آخر تحديث: 2026-09-18. المهمة 0005 / P2b في `feat/telegram-connection` وPR4. الشريحة النشطة: [الحساب داخل التطبيق](tasks/0005-connected-app.md)، خطتها `566cf53b` سبقت كودها. الحالة الآن: **الكود مكتوب، اختبارات الشريحة الجديدة تنتظر CI**. طلب المالك المتابعة داخل الجلسة دون انتظار ساعة؛ أوقفت مهمة التنفيذ الساعية لمنع التنافس. لا استمرار تلقائي مزعوم بعد انتهاء الجلسة.

## قراءة إلزامية

اقرأ AGENTS وهذه الذاكرة والبنية والخارطة والقرارات والأمان والقدرات وخطة المهمة والمصدر والاختبارات. [ACCOUNT_INTEGRATION](ACCOUNT_INTEGRATION.md) يوضح تحديث البنية والأمان والبناء لشريحة الحساب؛ لا تعتمد عبارة المعاينة القديمة وحدها بعد هذه الإضافة. افحص أحدث الفرع وCI والـdiff، ثم افهم وخطط ونفذ واختبر واقرأ الدليل ووثق. لا إعادة عمل منجز أو تخفيف اختبار لإخراج نجاح.

## الثوابت

BotOS عميل حساب مستخدم لبوتات Telegram عبر TDLib، لا Bot API ولا توكنات بوتات ولا AI يخمن callbacks. التصميم Porcelain/Graphite/Iris والأيقونة معتمدان في ADR-007 عند158c5258. حافظ على الألوان والثيمات وRTL والتبويبات ومفاتيح WorkspaceStore والأسماء وترتيبها. لا تغيير بصري جوهري دون موافقة.

BotOsApp وحده يملك union لمساحات النظام والكيبورد، ولا imePadding إضافي في الشاشات. الوجهات تجمع الحالة داخل NavEntry. لا /start عند كل تبديل ولا نقل أفعال قديمة إلى حساب أو بوت آخر.

## المنفذ

P2a مكتملة: TDLib/JSONJava ثابتان، TdRpc/TdTransport يربطان الطلب بالجواب ويرتبان التحديثات والمهلة والإلغاء دون إعادة الفعل. Authorization من تحديثات Telegram لا Ok. AndroidTelegramSession يملك الاستقبال حصريًا؛ SessionVault يحمي مفتاح قاعدة الجلسة عبر Keystore/AES-GCM. close يحفظ الجلسة؛ logOut يمحوها بعد الإقرار والإغلاق؛ تلف المفتاح لا يمحو ضمنيًا.

AccountCoordinator اختُبر قبل توصيل الشاشة: موافقة وتهيئة قبل الفتح، getMe بعد READY، عزل أجيال الجلسة، وإذن استعادة متسلسل لا يعاد تفعيله برد قديم بعد الخروج. الإلغاء والخروج وفشل التنظيف حالات منفصلة.

**الجديد المكتوب في شريحة connected-app:** BotOsApplication بمنسق واحد وفتح Native خارج مسار الرسم، AccountRestoreStore في noBackupFilesDir وملف منفصل، AccountViewModel وAccountRoute وواجهة موافقة وهاتف/كود/كلمة مرور/بريد من الحالة الفعلية. المدخلات remember مؤقتة لا saved state، وFLAG_SECURE أثناء إدخالها. الرجوع ليس خروجًا، والخروج يحتاج تأكيدًا. Manifest يربط Application وINTERNET وقواعد منع backup/device transfer. التهيئة الناقصة لا تعرض حقول الدخول.

app أصبح يعتمد وحدة TDLib في الكود، لكن **لم يُختبر هذا الربط الجديد بعد** ولم يُستخدم حساب مستخدم. المعاينة المحلية باقية منفصلة؛ عرض محادثات البوتات وأزرارها الحية لم يوصل بعد. لا ترسل APK المعاينة أو بناء PR غيرالمهيأ بوصفه النسخة المتصلة المنتظرة.

## بوابة الاختبارات الجديدة

يبقى36JVM و8native و3UI. أضيفت4حالات عرض حساب وموافقة ومدخلات مؤقتة/FLAG_SECURE وخروج، و2DataStore بملفات حقيقية معزولة، و1تنقل للحساب غيرالمهيأ: مجموع app device10. الاختبارات المصطنعة لا تثبت دخولًا حقيقيًا، وStateRestorationTester ليس محاكاة لموت العملية بالكامل.
